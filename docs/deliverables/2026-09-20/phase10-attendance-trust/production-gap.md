# 운영 적용 전 남은 항목

1. **회사 정책:** 실제 고정 공인 IP/CIDR, 재택·출장 승인 책임자, 정정 절차, PC 분실·퇴사 시 token 회수 시간을 확정한다. 기본 모드는 `DEVICE_AND_NETWORK`이며 CIDR/기기 미등록 시 출퇴근이 차단된다.
2. **Vercel ingress 검증:** Production/Preview에서 실제 `X-Forwarded-For`가 단일 고객 IP로 전달되고 원본 헤더가 덮어써지는지, 추가 CDN·프록시·VPN 경로가 없는지 통제된 계정으로 검증한다. 다른 호스팅에서는 현재 IP가 `UNKNOWN`이다.
3. **기기 배포:** 예제 Agent를 Windows 서비스/설치 패키지로 운영할지 결정하고 OS 비밀 저장소/TPM, 서명·업데이트, 실행 상태, token rotation/revoke, 단말 관리 절차를 설계한다. 현재 token은 host가 탈취되면 재사용 가능하다.
4. **남용/보관:** 증명 endpoint rate limit과 nonce·FAILED 시도 정리/보존 기간, 경보 임계치를 운영 정책에 따라 도입한다. 현재 nonce는 중복 방지용으로 계속 남고, 조회 화면은 최근 300건으로 제한된다.
5. **접근·개인정보:** 공인 IP와 실패 이유는 민감한 접속 기록이다. 관리자 접근, 감사 보존/삭제, 실제 개인 정보 입력 경로를 검토한다.
6. **오프사이트:** 현재 예외는 ADMIN이 직접 승인한 기록이다. 별도 원격근무/출장 결재 자동 연계는 아직 없으며 필요할 때 기존 Approval Engine을 확장한다.
7. **운영 검증:** 이 단계는 로컬 Supabase와 테스트 계정만 확인했다. 운영 DB migration, 실제 직원, 실제 Office IP, 설치 PC, 운영 Vercel, 모바일 차단 동작은 검증하지 않았다. Pilot은 계획하지 않았다.

브라우저 GPS, MAC, 사용자 입력 시간은 출퇴근 판정 근거로 사용하지 않는다. PC+네트워크를 충족해도 물리적 재실은 보증되지 않는다.
