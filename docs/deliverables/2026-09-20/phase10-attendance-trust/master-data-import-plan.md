# Phase 11 실데이터 입력 준비

## Canonical 양식

[`docs/templates/master-data/`](../../../templates/master-data/README.md)에 헤더만 있는 CSV 13개와 작성 가이드를 둔다. 조직, 직급, 직책, 직원, 역할/부여, 근무정책/배정, 자산/지급, 프로젝트/투입, 회사 CIDR을 포함한다. UUID 대신 조직 코드·사번·자산 코드·프로젝트 코드·정책 코드를 참조 키로 사용한다. 기존 조직의 nullable `code`가 비어 있으면 먼저 대응표를 확정한다. 실제 직원 데이터와 device token은 저장소 양식에 적지 않는다.

## 검증 전용 명령

`npm run import:master-data -- C:\secure\master-data`는 디렉터리 안의 CSV를 읽어 헤더, 필수값, 중복 업무키, 같은 묶음의 참조, 날짜/시간/enum, 조직 순환, 자산 중복 지급, 투입률 합계를 검사한다. 결과는 총 행/유효/경고/오류와 파일·행·컬럼을 제공하며 오류가 있으면 종료 코드 1이다. 100% 초과 투입은 경고다. 명령에 DB 쓰기 경로는 없으며 기본 빈 템플릿 실행은 0행이다.

## 실제 입력 단계

1. 회사가 접근 제한된 별도 복사본에 데이터를 작성한다.
2. Dry run 오류를 수정하고 투입률 경고를 담당자가 검토한다.
3. Phase 11에서 기존 운영 DB의 이메일·업무키·serial 중복과 관계를 읽기 전용으로 대조한다. Auth identity 생성/기존 직원 매핑과 역할 부여 순서를 확정한다.
4. 백업과 Preview 적용 결과를 검토하고 관리자 확인 후에만 실제 Import를 수행한다. 그때 기존 RPC/RLS/감사·멱등성을 재사용하는 적용 경로를 별도로 만든다.

이번 단계에서 실제 DB Import나 직원 Pilot은 실행하지 않았다.
